# Интернет-магазин на Django

Учебный проект: интернет-магазин с каталогом, корзиной, оформлением заказов
и личным кабинетом. Написан на Python и Django, данные хранятся в PostgreSQL.

Проект развивается как дипломная работа: к базовой функциональности магазина
добавляются интеллектуальные модули на основе языковых моделей — семантический
поиск, рекомендации, чат-консультант и аналитика отзывов.

**Автор:** Шевырев Д. С., КубГУ, ФКТиПМ.

## Возможности

- **Каталог** — товары по категориям, поиск, фильтрация, постраничный вывод.
- **Карточка товара** — описание, цена, изображение. Дополнительные фотографии
  можно добавить через админку, в демо-данных их нет.
- **Корзина** — работает и для гостей, и для зарегистрированных. У гостя лежит
  в сессии, у зарегистрированного сохраняется в базе и переживает выход с сайта.
- **Заказы** — оформление, история, отмена. Цена фиксируется в момент покупки:
  если товар потом подорожает, в старом заказе останется прежняя сумма.
- **Личный кабинет** — профиль с адресом доставки, история заказов.
- **Админка** — управление товарами, категориями, заказами и статусами.

## Установка

### Требуется

- Python 3.13
- PostgreSQL 18 (запущенная служба)

### 1. Скачать проект

```
git clone -b diploma https://github.com/DmitriyShevyrev/kursovoi_project.git
cd kursovoi_project
```

### 2. Виртуальное окружение и зависимости

```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Создать базу данных

Выполните в psql или pgAdmin — **по одной команде за раз**:

```sql
CREATE ROLE kursovoi_user WITH LOGIN PASSWORD 'ваш_пароль' CREATEDB;
CREATE DATABASE kursovoi OWNER kursovoi_user ENCODING 'UTF8';
```

Вместе их выполнять нельзя: pgAdmin оборачивает запрос в транзакцию, а
`CREATE DATABASE` внутри транзакции запрещён — откатится и создание роли.

Право `CREATEDB` нужно не сайту, а тестам: Django создаёт для них временную
базу `test_kursovoi` и удаляет после прогона.

### 4. Настроить `.env`

Скопируйте образец:

```
copy .env.example .env
```

Сгенерируйте ключ подписи и впишите его в `SECRET_KEY`:

```
venv\Scripts\python.exe -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

В `DB_PASSWORD` впишите пароль, который задали при создании роли.

Без `.env` проект намеренно не запустится: значения по умолчанию для `SECRET_KEY`
в коде нет, чтобы секрет не мог попасть в репозиторий.

### 5. Развернуть базу и запустить

```
python manage.py migrate
python manage.py loaddata catalog.json
python manage.py createsuperuser
python manage.py runserver
```

Магазин откроется на http://127.0.0.1:8000, админка — на `/admin/`.

Команда `loaddata` наполнит каталог демо-данными: 5 категорий и 52 товара.
Изображения к ним лежат в `media/products/` и хранятся прямо в репозитории —
иначе после клонирования каталог показывал бы пустые карточки.

## Структура

```
config/     настройки проекта, корневые маршруты
catalog/    товары, категории, поиск, фильтрация
cart/       корзина: сессия + база, синхронизация через сигналы
orders/     оформление, статусы, история, отмена
users/      регистрация, вход, профиль
docs/       описание проекта и план работ
media/      изображения товаров
logs/       логи (в репозиторий не попадают)
```

## Персональные данные

Проект работает с персональными данными покупателей (имя, фамилия, адрес
доставки), поэтому обращение с ними ограничено:

- **В логи ПДн не пишутся.** Только идентификаторы: `order_id=42 user_id=7`.
  Лог — такое же хранилище данных, как база, но защиты у него нет, а скопировать
  его легко. Запрет закреплён автотестами.
- **Секреты не хранятся в коде.** `SECRET_KEY` и пароль базы лежат в `.env`,
  который исключён из репозитория.
- Планируемые модули на основе языковых моделей получают только данные каталога
  и обезличенный текст: ФИО, адреса и телефоны за пределы проекта не уходят.

Это соответствует принципу минимизации персональных данных (152-ФЗ).
